# PRD: 투싼용 Android Auto 앱 캐스팅 (가칭 "AutoCast")

- 버전: 0.1 (초안)
- 작성일: 2026-11-22
- 대상 차량: 2025년식 현대 투싼 (ccNC, Android Auto 지원)
- 상태: 기술 검증(Phase 0) 전. "⚠ 미검증" 표시는 실차 테스트로 확인해야 하는 항목입니다.

---

## 1. 배경과 문제

- 2025 투싼 ccNC에는 범용 웹브라우저가 확인되지 않습니다. 그래서 Tesor처럼 차 브라우저로 스트리밍하는 방식은 쓸 수 없습니다.
- Android Auto(AA)는 Google이 허용한 앱 카테고리(내비, 미디어, 메시징 등)만 차 화면에 띄웁니다. 그 밖의 폰 앱(웹툰, 브라우저, 사내 앱, 주차 중 영상 등)은 차 화면에서 쓸 수 없습니다.
- 기존 화면 미러링 앱은 폰 화면 자체를 복제하기 때문에, 미러링하는 동안 폰을 따로 쓸 수 없습니다.

## 2. 목표

1. 폰에 있는 아무 앱이나 AA를 통해 투싼 화면에 띄웁니다.
2. 폰 화면은 독립적으로 유지합니다. 차 화면 전용 가상 디스플레이를 씁니다.
3. 차 터치스크린 입력으로 그 앱을 조작합니다.
4. 루팅 없이 동작합니다. 개발자 옵션의 무선 디버깅으로 권한을 얻습니다.

### 비목표 (MVP 범위 밖)
- Google Play 배포. 이 방식은 Play 정책상 배포할 수 없으므로 사이드로드 전용입니다.
- DRM 앱 재생(Netflix 등). FLAG_SECURE 때문에 기술적으로 불가능하고 우회하지 않습니다.
- iOS / CarPlay.
- 차량 CAN 데이터 연동.

## 3. 사용자

- 1차: 개발자 본인(투싼 2025 + Android 폰). 개인용으로 사이드로드해 씁니다.
- 2차(Phase 3 이후 검토): 같은 차종을 타는 기술 친화적 사용자. 웹사이트나 GitHub Releases로 APK를 배포합니다.

## 4. 핵심 사용 시나리오

1. **최초 설정 (1회):** 앱을 설치하고, 개발자 옵션 → 무선 디버깅 페어링을 마칩니다. 그다음 AA 개발자 설정에서 "알 수 없는 출처"를 켭니다.
2. **일상 사용:** 차에 탑승해 AA를 연결합니다(유선 또는 무선). AA 런처에서 AutoCast를 엽니다. 앱 그리드에서 앱을 고르면 차 화면에 표시됩니다.
3. **폰 독립 사용:** 차 화면에 앱 A가 떠 있는 동안 동승자나 운전자(정차 중)는 폰에서 앱 B를 씁니다.
4. **재부팅 후:** Wi‑Fi에 한 번 연결하면 백그라운드에서 자동으로 다시 페어링됩니다.

## 5. 아키텍처

```
┌─────────────── 폰 ───────────────────────────────────────────┐
│                                                             │
│  [AutoCast 앱 프로세스]                                      │
│   ├─ CarAppService (카테고리: NAVIGATION)                    │
│   │    └─ SurfaceCallback → AA가 준 Surface 수신             │
│   ├─ 설정/페어링 UI (Activity)                               │
│   └─ AIDL 클라이언트 ── Surface(Parcelable) 전달 ──┐          │
│                                                   ▼          │
│  [Shell 권한 헬퍼 프로세스] (무선 디버깅 ADB로 app_process 실행)│
│   ├─ DisplayManager.createVirtualDisplay(surface=AA Surface) │
│   ├─ am start --display <id> 로 대상 앱 실행                 │
│   └─ InputManager.injectInputEvent(displayId 지정)           │
│                                                             │
└──────────────── AA 프로젝션 (USB/Wi‑Fi) ─────────────────────┘
                         ▼
              투싼 ccNC 화면 (AA 화면)
```

### 핵심 설계 결정
- **인코더가 필요 없습니다.** 가상 디스플레이의 출력 Surface로 AA가 준 Surface를 직접 씁니다. 영상 인코딩과 전송은 AA가 처리합니다. Tesor와의 가장 큰 차이입니다.
- **오디오 작업이 필요 없습니다.** AA가 연결된 동안 폰의 미디어 오디오는 AA 채널로 차에 전달됩니다. ⚠ 미검증: 가상 디스플레이에서 실행된 앱의 오디오도 같은 경로로 나가는지 확인해야 합니다.
- **권한은 Shell 헬퍼가 가집니다.** 다른 앱을 띄울 수 있는 가상 디스플레이를 만들고 입력을 주입하려면 shell(uid 2000) 권한이 필요합니다. 그래서 무선 디버깅으로 자기 자신에게 ADB 연결을 맺고 `app_process`로 헬퍼를 실행합니다. 구현 방식은 직접 구현과 Shizuku 연동 중에 고르며, 열린 질문 Q1에서 다룹니다.

## 6. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F1 | AA 런처에 앱 아이콘으로 표시 (NAVIGATION 카테고리, `androidx.car.app.ACCESS_SURFACE` 권한) | P0 |
| F2 | AA Surface 크기와 DPI에 맞춰 가상 디스플레이 생성, 해상도 변경 시 재생성 | P0 |
| F3 | 앱 선택 런처: 설치된 앱 그리드를 가상 디스플레이에 표시 | P0 |
| F4 | 선택한 앱을 가상 디스플레이에 실행 | P0 |
| F5 | 터치 입력: AA `onClick` → 탭, `onScroll` → 드래그/스크롤, `onFling` → 플링, `onScale` → 핀치 | P0 |
| F6 | 뒤로가기/홈 버튼 (화면 가장자리 오버레이 또는 AA 액션 스트립) | P0 |
| F7 | 무선 디버깅 페어링 가이드와 자동 재페어링 | P0 |
| F8 | 헬퍼 프로세스 상태 모니터링과 자동 재시작 | P1 |
| F9 | 화면 분할 / 프리폼 창 (데스크톱 모드) | P2 |
| F10 | 자동 시작: AA 연결 시 마지막 앱 복원 | P1 |
| F11 | 텍스트 입력: 폰 키보드 사용 또는 음성 입력 | P2 |

## 7. 안전 요구사항 (필수)

| ID | 요구사항 |
|---|---|
| S1 | 주행 중에는 영상·게임 등 시각 주의를 크게 끄는 앱을 차단하거나 정지 화면으로 전환합니다. 정차 중(속도 0)에만 허용합니다. |
| S2 | 주행 판정에는 폰 GPS 속도를 기본으로 쓰고, 가능하면 Car App Library의 차량 정보(CarHardwareManager)를 씁니다. ⚠ 미검증: 투싼에서 속도나 기어 정보가 제공되는지 확인해야 합니다. |
| S3 | 사용자가 앱별로 "주행 중 허용" 목록을 설정합니다. 기본값은 비허용입니다. |
| S4 | 최초 실행 시 안전·법규 고지에 동의를 받습니다. 운전 중 영상 시청은 도로교통법 위반입니다. |

## 8. 비기능 요구사항

- **지원 폰:** Android 11 이상(무선 디버깅 페어링이 Android 11부터). 주력 테스트 기기는 Samsung One UI입니다.
- **지연:** 터치부터 화면 반영까지 150ms 이하를 목표로 합니다(AA 자체 지연 포함).
- **안정성:** 1시간 주행 중 헬퍼 프로세스 크래시 0회.
- **발열과 배터리:** 인코딩을 하지 않으므로 일반 AA 내비 사용 수준을 목표로 합니다.

## 9. 알려진 제약과 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| AA 입력 API가 탭/스크롤/플링/핀치만 제공하고, 롱프레스·멀티터치 드래그 등이 없음 | 일부 앱 조작이 어려움 | 롱프레스 모드 토글 같은 UI 보조 제공 |
| Google이 AA 개발자 모드나 사이드로드 앱 정책을 바꿀 수 있음 | 앱이 동작하지 않게 될 수 있음 | 개인용 MVP 전제, 지속적인 대응 필요 |
| AA 화면 해상도가 낮음(800×480 / 1280×720 / 1920×1080) | 화질 | AA 개발자 설정에서 최대 해상도 사용 안내 |
| 재부팅 후 Wi‑Fi가 없으면 페어링 불가 | 사용 불편 | 가이드 제공, 핫스팟 우회 방안 검토 |
| 제조사별 가상 디스플레이 동작 차이(특히 Samsung) | 일부 앱이 뜨지 않음 | 기기별 테스트 매트릭스 운영 |
| Surface를 다른 프로세스(shell)로 넘겼을 때의 동작 | 핵심 구조가 깨질 수 있음 | Phase 0에서 가장 먼저 검증 |

## 10. 단계별 계획

### Phase 0: 기술 검증 (1~2주)
목표는 "투싼 화면에 폰의 아무 앱이나 한 번 띄워 보기"입니다.
1. AA NAVIGATION 앱으로 Surface를 받아 단색과 텍스트를 그립니다. 투싼에서 사이드로드 앱이 보이는지 확인합니다.
2. adb shell로 헬퍼를 실행하고, AA Surface를 넘겨받아 가상 디스플레이를 만든 뒤 계산기 앱을 실행합니다.
3. `onClick`을 탭 주입으로 연결합니다.
4. 오디오가 차로 나오는지 확인합니다.

종료 조건: 1~4가 모두 투싼 실차에서 동작해야 합니다. 하나라도 실패하면 아키텍처를 다시 봅니다.

### Phase 1: MVP (3~4주)
F1~F7과 S1~S4 구현, 무선 디버깅 자가 페어링, 앱 런처.

### Phase 2: 사용성 (3주)
F8, F10, F11, 롱프레스 보조, 기기 호환성 테스트.

### Phase 3: 배포 검토
F9, 웹사이트나 GitHub Releases 배포 여부, 유료화 여부 결정.

## 11. 열린 질문

- **Q1. 헬퍼 실행 방식:** Shizuku 연동(설치 부담은 있지만 검증된 방식) 대 무선 디버깅 ADB 클라이언트 직접 구현(단일 앱으로 끝나지만 구현량이 많음). 권장은 MVP에서 Shizuku, Phase 2 이후 직접 구현입니다.
- **Q2.** 투싼 ccNC에서 AA를 무선으로 연결했을 때와 유선으로 연결했을 때 해상도와 지연에 차이가 있는지.
- **Q3.** 투싼에서 주행 상태 정보(속도, 기어)를 Car App Library로 받을 수 있는지.
- **Q4.** 최종 배포 범위: 개인용인지, 외부 배포인지, 유료인지.

## 12. 참고 자료
- Android for Cars App Library: 내비게이션 앱의 Surface 접근(`SurfaceCallback`)
- scrcpy (Apache 2.0): shell 권한 가상 디스플레이와 입력 주입 구조 참고
- Shizuku: shell 권한 서비스 실행 참고
- Tesor: 제품 컨셉 참고만 하고, 코드는 사용하지 않습니다(비공개 유료 앱).
